## Directories

`Directory.root()` returns the directory the runtime bound for this component. A `Directory` is a
working directory rather than a sandbox: paths resolve against it, `"."` names the directory
itself, and `".."` names its parent. What limits reach is the authority the mount grants, and a
path that resolves outside it raises `PathEscapesAuthorityError`.

```python
from agentc_fs import Directory


async def save(project: str, contents: str) -> None:
    projects = await Directory.root().mkdir(
        f"projects/{project}",
        parents=True,
        exist_ok=True,
    )

    await projects.write_text("notes.md", contents)
```

`open_dir`, `mkdir`, and `mkdtemp` return a `Directory`, so reaching a subdirectory means opening
it. `scandir` and `walk` list the directory they are called on and take no path.

Every path argument accepts `str | os.PathLike[str]`, so `pathlib.PurePosixPath` joins paths
without touching the filesystem. Paths come back as `str`, with each byte that is not valid UTF-8
replaced by `U+FFFD`.

## Open files

`Directory.open` returns a `File` with its own cursor. Use `async with` so the file is flushed and
closed when the block exits.

```python
from os import SEEK_END

from agentc_fs import Directory


async def tail(logs: Directory, name: str, size: int) -> bytes:
    async with await logs.open(name) as file:
        await file.seek(-size, SEEK_END)

        return await file.read()
```

Calls on one `File` run one at a time, in the order they started. Separate files have independent
cursors and run concurrently. After `close`, `closed` is `True`, another `close` does nothing, and
every other method raises `UnsupportedError`.

## Exceptions

```text
FilesystemError
├── NotFoundError
├── AlreadyExistsError
├── NotDirectoryError
├── IsDirectoryError
├── PermissionDeniedError
├── PathEscapesAuthorityError
├── CrossBackendRenameError
├── InvalidPathError
├── UnsupportedError
└── UnexpectedError
```

Failures that concern one path retain that path. A rename across backends retains both. Catch
`FilesystemError` for all filesystem failures, or catch the narrower class when recovery depends on
the failure type.
