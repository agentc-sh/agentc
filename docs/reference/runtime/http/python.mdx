`agentc_http` provides an asynchronous HTTP client. Requests use the runtime's egress policy and
limits.

## Request lifecycle

Use an absolute URL with a client that has no `base_url`, or use relative URLs with a client that
has one. A base URL is treated as a directory, so `https://api.example.com/v1` and `/users` produce
`https://api.example.com/v1/users`.

```python
from agentc_http import Client

client = Client(base_url="https://api.example.com/v1")

async with client.get("/users", params={"active": True}) as response:
    response.raise_for_status()
    users = await response.body.json()
```

A `PendingResponse` is single-use. `async with` closes an unread response body when the block exits.
When awaiting directly, call `response.close()` if the body will not be consumed.

## Client

```python
Client(
    *,
    base_url: str | None = None,
    headers: HeaderTypes | None = None,
    params: QueryParams | None = None,
    timeout: float | None = None,
)
```

Client headers and query parameters are defaults. Request values replace defaults with the same
name, including all repeated values for that name. Query parameters are appended after a query
already present in the URL. A request timeout can shorten the runtime's configured whole-request
deadline but cannot extend it.

`get`, `head`, and `options` accept `url`, `params`, `headers`, and `timeout`. `delete`, `post`, `put`,
and `patch` also accept `body`. `send(request)` applies the same defaults to an explicit `Request`.

## Request bodies

| Value | Encoding | Default `Content-Type` |
| ----- | -------- | ---------------------- |
| `bytes` | unchanged | none |
| `str` | UTF-8 | `text/plain; charset=utf-8` |
| `Json(value)` | JSON | `application/json` |
| `Form(fields)` | form URL encoding | `application/x-www-form-urlencoded` |
| `AsyncIterable[bytes]` | streamed chunks | none |

An explicit `Content-Type` header wins. A streamed body can be sent once.

## Response

`Response` exposes `status`, `reason`, `is_success`, `url`, `headers`, `request`, and `body`.
`raise_for_status()` returns the same response for a successful status and raises `HTTPStatusError`
otherwise. `close()` releases an unread body.

`ResponseBody.read()`, `text()`, and `json()` consume the full body. Iterating the body yields byte
chunks. `text_chunks()` yields incrementally decoded text and `lines()` yields universal-newline
lines. Only one consuming operation may start. `consumed` and `closed` report the shared body state.

## Headers and parameters

`Headers` implements `Mapping[str, str]`. Lookup is case-insensitive. `get_list(name)` returns every
value for one name, while `multi_items()` returns every name-value pair including repeats.

Query parameters accept a mapping or a sequence of pairs. Booleans encode as `true` or `false`,
`None` as an empty value, and a sequence value repeats its key.

## Exceptions

```text
HTTPError
├── RequestError
│   ├── TransportError
│   │   └── TimeoutException
│   ├── RequestDenied
│   ├── TooManyRedirects
│   └── InvalidRequest
└── ResponseError
    ├── HTTPStatusError
    ├── DecodingError
    └── ResponseTooLarge

RuntimeError
└── BodyError
    ├── BodyConsumed
    └── BodyClosed
```

Request failures retain the originating `Request`. Status and response-body failures retain the
originating `Response`. Catch `HTTPError` for all HTTP-client failures, or catch the narrower class
when recovery depends on the failure type.

<LibSignature>
```python
async for chunk in body: ...                  # bytes

body.lines() -> AsyncIterator[str]

await body.text() -> str
await body.json() -> Any
```
</LibSignature>

`text()` and the text iterators use the response `Content-Type` charset. A missing or unknown
charset defaults to UTF-8, and malformed input uses replacement characters. `json()` reads JSON
from the response bytes and does not use the text charset.
