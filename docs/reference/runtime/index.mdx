The runtime provides these libraries to every component it executes. Each library has its own page
describing what it does and a page per language describing its surface.

## Libraries

| Library | Purpose | Languages |
| ------- | ------- | --------- |
| [agentc:fs](/reference/runtime/fs) | A POSIX-style virtual filesystem assembled by the runtime. | TypeScript |
| [agentc:http](/reference/runtime/http) | An HTTP client whose outbound requests pass the runtime's egress policy. | TypeScript |

## How the libraries are bound

Any compiled output containing a TypeScript component contains both libraries. The
manifest controls what each library does, which is the filesystem's contents and the network's
policy, not whether the library is present.

## The language's own surface

The runtime also implements a subset of the language's standard library. That subset is enumerated
in [Standard library](/reference/runtime/standard).

## Editor support

`@agentc-sh/runtime` is a type stub package. It carries TypeScript declarations for the runtime
surface and no implementation, so an editor reports what the runtime actually provides.

Depending on it is optional. A component that does not depend on it compiles and runs identically,
and the only thing its absence costs is editor knowledge.

Installing it requires a version of `11.10.0` or later for npm and `9.0.0` for pnpm, because it
resolves as a git subdirectory dependency and older versions do not honor the subdirectory fragment.
