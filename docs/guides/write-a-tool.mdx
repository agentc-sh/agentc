title: Write a tool
description: Write a custom tool for your agent in TypeScript or Python.
---

Tools you write in code come in two languages, TypeScript and Python. This guide covers both. Pick the
tab for your language in each step. Both kinds are bundled into the binary at compile time, so there is
no runtime installation. For the full field reference, see the [tool reference](/reference/manifest/tool).

TypeScript tools run in an embedded JavaScript runtime. Python tools use RustPython by default,
which supports pure-Python packages and needs no Python installation at runtime. Select the
`static` interpreter to use CPython 3.14 for packages with C extensions. Both use the agentc tool
development kit (TDK), which gives you typed tool definitions.

## Scaffold the package

Generate a ready-to-use package with `agentc tool init`, then install its dependencies.

<Tabs defaultValue="typescript">
  <TabsList>
    <TabsTrigger value="typescript">TypeScript</TabsTrigger>
    <TabsTrigger value="python">Python</TabsTrigger>
  </TabsList>
  <TabsContent value="typescript">
```bash
agentc tool init math --language javascript
cd math
pnpm install
```

This creates a `package.json`, a `tsconfig.json`, `src/index.ts`, and `src/agentc-env.d.ts`, with the
TDK, esbuild, and the runtime type declarations already configured.

The scaffolded `package.json` declares `"packageManager": "pnpm@11.1.2"`, and the compiler installs
your dependencies with whichever manager that field names. If you change it to npm, also change the
`@agentc-sh/runtime` specifier's `&` separator to `::`, because the two managers spell a git
subdirectory differently. Both forms are given in that package's README.
  </TabsContent>
  <TabsContent value="python">
```bash
agentc tool init weather --language python
cd weather
uv sync
```

This creates a `pyproject.toml` and a typed package directory, with the TDK dependency and build
system already configured.
  </TabsContent>
</Tabs>

## Write the tool

A tool has a name, a description, a JSON Schema for its inputs, and an `execute` function. The name and
descriptions are what the model reads to decide when and how to call it, so write them carefully.

<Tabs defaultValue="typescript">
  <TabsList>
    <TabsTrigger value="typescript">TypeScript</TabsTrigger>
    <TabsTrigger value="python">Python</TabsTrigger>
  </TabsList>
  <TabsContent value="typescript">
Export a tool object from the package entry point. Import the `Tool` type from the TDK for full type
coverage.

```typescript title="math/src/index.ts"
import type { Tool, ToolInput, ToolOutput } from "@agentc-sh/tdk";

type AddArgs = { a: number; b: number };

export const adder: Tool<AddArgs, number> = {
  name: "adder",
  description: "Adds two numbers together.",
  parameters: {
    type: "object",
    properties: {
      a: { type: "number", description: "The first number." },
      b: { type: "number", description: "The second number." }
    },
    required: ["a", "b"]
  },
  async execute(input: ToolInput<AddArgs>): Promise<ToolOutput<number>> {
    return { output: input.args.a + input.args.b };
  }
};
```

A single package can export as many tools as you need.
  </TabsContent>
  <TabsContent value="python">
Subclass `Tool` and implement `execute`. The generic parameters are the argument type, the result
type, and the state type.

```python title="weather/weather/__init__.py"
from dataclasses import dataclass
from agentc_tdk import Tool, ToolInput, ToolOutput


@dataclass
class GetWeatherParams:
    location: str

@dataclass
class GetWeatherResult:
    temperature: float
    description: str


class GetWeatherTool(Tool[GetWeatherParams, GetWeatherResult, None]):
    args = GetWeatherParams

    name = "get_weather"
    description = "Get the current weather for a given location."
    schema = {
        "type": "object",
        "properties": {
            "location": {"type": "string", "description": "The location to get the weather for."},
        },
        "required": ["location"],
    }

    def execute(self, input: ToolInput[GetWeatherParams, None]) -> ToolOutput[GetWeatherResult]:
        return ToolOutput(
            output=GetWeatherResult(temperature=72.0, description=f"Sunny in {input.args.location}")
        )
```

A single package can define as many tool classes as you need.
  </TabsContent>
</Tabs>

## What the TypeScript runtime provides

TypeScript tools do not run in Node. They run in an embedded JavaScript engine, and the environment
they see is assembled by the host, so it is neither Node's nor a browser's. The runtime libraries the
host does provide live under the `agentc:` prefix and are imported like any other module.

```typescript title="math/src/index.ts"
import { fetch } from "agentc:http";

const response = await fetch("https://example.com");
```

`agentc:http` also installs `fetch`, `Headers`, and `Response` as globals, as the same values it
exports, so the import is optional for those three.

```typescript title="math/src/index.ts"
const response = await fetch("https://example.com");
```

Alongside these, the host binds a set of Node-compatible modules: `node:buffer`, `node:console`,
`node:timers`, `node:url`, `node:os`, `node:stream/web`, `node:fs`, and `node:fs/promises`. Each is a
subset of its Node counterpart rather than a full implementation.

The shapes of all of it come from `@agentc-sh/runtime`, which the scaffold installs and references for
you, so your editor reports what the host actually provides rather than guessing.

<Callout type="note" title="`@types/node` is deliberately absent">
The scaffold does not depend on `@types/node`, and its `tsconfig.json` sets `types` to an empty array
so nothing pulls it in. The guest is not a Node process, and `@types/node` describes a great deal that
the host never binds.
</Callout>

## Declare the tool in the manifest

The package exists, but the agent does not see it until you declare a `tool` block pointing `source` at
the package directory.

<Tabs defaultValue="typescript">
  <TabsList>
    <TabsTrigger value="typescript">TypeScript</TabsTrigger>
    <TabsTrigger value="python">Python</TabsTrigger>
  </TabsList>
  <TabsContent value="typescript">
```hcl title="agent.acl"
tool "adder" {
  kind   = "javascript"
  source = "./math"
}
```

The block name matches the export name by default. If they differ, set `export` to the export name.
  </TabsContent>
  <TabsContent value="python">
```hcl title="agent.acl"
tool "get_weather" {
  kind        = "python"
  source      = "./weather"
  interpreter = "embedded"
}
```

Declare one `tool` block per tool class, all pointing at the same `source` directory. Change
`interpreter` to `"static"` when the package requires CPython or a C extension. The runtime host
must provide a compatible shared CPython 3.14 installation.
  </TabsContent>
</Tabs>

## Write back to state

A tool can return a `state_update` alongside its output: an array of RFC 6902 JSON Patch operations.
For the ReAct graph, target paths under `/context/`. The patches are persisted and streamed to the
client as state delta events, which is how a tool passes data to a frontend.

<Tabs defaultValue="typescript">
  <TabsList>
    <TabsTrigger value="typescript">TypeScript</TabsTrigger>
    <TabsTrigger value="python">Python</TabsTrigger>
  </TabsList>
  <TabsContent value="typescript">
```typescript
async execute(input: ToolInput<AddArgs>): Promise<ToolOutput<number>> {
  return {
    output: input.args.a + input.args.b,
    state_update: [
      { op: "add", path: "/context/last_sum", value: input.args.a + input.args.b }
    ]
  };
}
```
  </TabsContent>
  <TabsContent value="python">
```python
def execute(self, input: ToolInput[GetWeatherParams, None]) -> ToolOutput[GetWeatherResult]:
    return ToolOutput(
        output=GetWeatherResult(temperature=72.0, description="Sunny"),
        state_update=[
            {"op": "add", "path": "/context/last_location", "value": input.args.location}
        ],
    )
```
  </TabsContent>
</Tabs>

## Build

Rebuild so the tool is bundled into the binary:

```bash
agentc build
```
